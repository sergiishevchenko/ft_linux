# 00. Введение

## Что такое Linux From Scratch

**Linux From Scratch (LFS)** — методика сборки своей Linux-системы из исходных кодов. Ты не ставишь готовый дистрибутив пакетами из репозитория. Ты:

1. Берёшь исходники (ядро, glibc, gcc, coreutils…)
2. Компилируешь их в правильном порядке
3. Получаешь минимальную, но рабочую ОС

Цель LFS — понять, **из чего состоит Linux** и как части связаны: toolchain → C library → утилиты → init → ядро → bootloader.

## Что такое ft_linux (42)

Проект `ft_linux` требует собрать свой дистрибутив, который потом станет базой для kernel-проектов. Обязательные требования (кратко):

- ядро >= 4.0, в версии есть твой **student login**
- исходники ядра в `/usr/src/kernel-<version>`
- бинарник: `/boot/vmlinuz-<version>-<login>`
- hostname = login
- минимум 3 раздела: `/`, `/boot`, swap
- загрузчик (GRUB/LILO)
- udev/eudev
- SysVinit или systemd
- иерархия по FHS
- интернет, возможность качать исходники

Это почти полностью покрывается путём **LFS SysV**.

## Три среды сборки

Понимание этих трёх миров — ключ ко всему учебнику.

```text
┌─────────────────────────────────────────┐
│ 1. HOST                                 │
│ Обычный Linux в VM (Debian и т.п.)      │
│ Здесь: разметка диска, кросс-компиляция │
└──────────────────┬──────────────────────┘
                   │ chroot
┌──────────────────▼──────────────────────┐
│ 2. CHROOT ($LFS как /)                  │
│ Уже «будущая» система                   │
│ Здесь: финальные пакеты, ядро, GRUB     │
└──────────────────┬──────────────────────┘
                   │ reboot
┌──────────────────▼──────────────────────┐
│ 3. BOOTED ft_linux                      │
│ Самостоятельная ОС                      │
└─────────────────────────────────────────┘
```

## Зачем кросс-компиляция

Если сразу собирать всё хост-ным GCC в `/mnt/lfs`, новые программы будут зависеть от библиотек хоста. После reboot эти библиотеки исчезнут — система сломается.

Поэтому LFS сначала строит **независимый toolchain** под цель `x86_64-lfs-linux-gnu`, потом временные инструменты, потом входит в chroot и собирает «настоящую» систему уже внутри неё.

## Как читать дальше

1. Не пропускай главы про `$LFS` и пользователя `lfs` — от них зависят все скрипты.

3. Делай snapshot VM после успешных фаз 4, 5, 7, 9.
